Venstar Thermostat (Local API) — v1.1.0

Controls Venstar ColorTouch, Explorer and commercial Wi-Fi thermostats directly over the Venstar Local API, using the Control4 thermostatV2 proxy. No cloud account is used.

Thermostat setup

  1. On the thermostat: Menu > Wi-Fi > Local API Options, set Local API to On.
  2. Give the thermostat a DHCP reservation so its IP address does not change.
  3. Optional: enable Local API authentication (HTTPS with username/password), and/or a Screen Lock PIN.

Driver setup

  1. Add the driver to the project and enter the IP Address.
  2. If Local API authentication is on, set Use HTTPS to Yes and enter Username and Password (Digest authentication is handled automatically).
  3. If Screen Lock is on, enter the Screen Lock PIN.
  4. Use the Test Connection action, then confirm Driver Status shows Online.

Properties

Poll Interval (seconds)Default 30. Each cycle reads /query/info and /query/sensors; alerts every 4th cycle. Requests are serialized because the thermostat does not handle concurrent requests.

Setpoint changes from Navigator are combined for 0.7 s so repeated taps produce a single request. The cool setpoint is kept at least setpointdelta above the heat setpoint; raising heat pushes cool up and lowering cool pushes heat down, as on the thermostat itself.

Connections

Indoor Temperature, Indoor Humidity and Outdoor Temperature outputs can be bound to other drivers that accept sensor values.

Programming

Events: Communication Lost / Restored, Air Filter Alert, UV Lamp Alert, Service Alert, All Alerts Cleared, Away Mode On / Off.

Commands: Refresh Now, Set Away Mode (On/Off/Toggle), Set Schedule (Run Schedule / Permanent Hold), Set Humidify Setpoint, Set Dehumidify Setpoint.

Variables: CONNECTED, HVAC_STATE, HVAC_ACTIVITY, HEAT_SETPOINT, COOL_SETPOINT, HUMIDITY, OUTDOOR_TEMPERATURE, AWAY, SCHEDULE_RUNNING, FILTER_ALERT, UV_LAMP_ALERT, SERVICE_ALERT.

Notes

  • T2xxx/T3xxx thermostats on firmware older than 5.28 report Celsius in the API regardless of display units; the driver detects this from model and firmware.
  • Commercial thermostats do not support Away; occupancy (holiday, override, forced unoccupied) is shown read-only.
  • Control4 scheduling presets are not used; the thermostat's own schedule stays in charge unless a hold is set.
